# 成本核算：价格记录可修改、初始价设置与趋势图样式 设计

- 日期：2026-11-12
- 状态：方案已于 2026-11-12 经用户确认
- 范围：后端（Go）、新前端（web/src）、经典版（web/classic）。经典版只改价格记录相关部分，不改图表。

## 1. 背景

1. 价格记录（`channel_cost_versions`）只能新增和删除。`POST /api/cost/channels/:id/versions` 拒绝 `effective_from=0`，补录表单又必须选日期，所以初始价删了补不回来，设错了只能删。
2. 渠道 `setting` 里也存着一份成本价（`cost_mode/cost_ratio/cost_discount/cost_exchange_rate`），渠道编辑页显示的就是它。`UpdateChannel` 保存后调用 `appendCostVersionIfChanged`：只要提交的成本价和**此刻生效的版本**不同，就从现在起追加一条版本。补录一条更晚的记录、删掉最新那条记录之后，setting 与生效版本不一致，此时在渠道编辑页做一次无关保存（比如改密钥），就会按旧价追加版本，成本悄悄回到旧价。加了「修改」之后这种情况会更常见。
3. 收支趋势图是直线、无填充，和数据看板「模型调用分析」的样式不一致；渠道成本构成只用 5 个主题色循环，渠道超过 5 个就会撞色。

## 2. 目标与非目标

目标：
- 任一价格记录（含初始）都能修改；初始价可以重新设置；删除前确认；增删改留审计。
- 价格记录变动后，渠道设置里的成本价与此刻生效的价保持一致；无关保存不再追加版本。
- 新前端两张成本图改成数据看板卡片样式。

非目标：
- 不改表结构（不加 updated_at/updated_by 列，改动记录靠审计日志）。
- 不支持把带日期的记录改成初始记录，也不支持反向操作。
- 经典版图表不改。

## 3. 后端

### 3.1 接口（均在 `/api/cost` 下，沿用 `CostAccountingEnabled` + `RootAuth`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/channels/:id/versions` | 新增记录。新增：允许 `effective_from=0`（渠道还没有初始记录时）；拒绝负数 |
| PUT | `/versions/:vid` | **新增**：修改记录 |
| DELETE | `/versions/:vid` | 不变：最后一条仍不可删 |
| PUT | `/channels/:id/price` | **新增**：设置当前价（成本页弹窗上半部分） |

### 3.2 校验

新增和修改共用：
- `cost_mode` 只能是 `""`、`ratio`、`discount`。
- 倍率模式 `cost_ratio > 0`；折扣模式 `cost_discount > 0`。
- `note` 不超过 255 个字符（按字符数）。

结算汇率：
- POST 保持现状：折扣模式没传汇率时退回站点 `USDExchangeRate`，仍非正则拒绝。
- PUT 与设置当前价：折扣模式必须传 `exchange_rate > 0`，不回退。修改历史记录时回退会悄悄改掉它冻结的汇率。
- 倍率模式不使用汇率，前端也不再显示汇率输入框。

生效时间（修改）：
- 初始记录（`effective_from=0`）只能保持 0；带日期的记录必须大于 0。
- 改了时间时，同一渠道不能已有相同时间的记录。

### 3.3 model（`model/channel_cost_version.go`）

- `UpdateChannelCostVersion(v *ChannelCostVersion) error`：事务内用 `lockForUpdate` 锁住该渠道全部版本行，重新定位目标行，校验初始时间不变、时间不冲突，再用 `Select(...).Updates` 写入（零值也要写，例如改成折扣模式后 `cost_ratio=0`）。错误：`ErrVersionNotFound`、`ErrInitialVersionTime`、`ErrVersionTimeTaken`。
- `DeleteChannelCostVersionIfNotLast`：把直接写的 `clause.Locking` 换成 `lockForUpdate`（项目规则），行为不变。
- `SyncChannelCostSetting(channelId int, now int64) error`：取 `now` 时刻生效的版本（早于最早记录时按最早那条），写回 `channels.setting`：以 map 读写，保留其它键；倍率模式删除 `cost_exchange_rate`，折扣模式写入版本冻结的汇率。没有版本时不动。

### 3.4 controller

- `appendCostVersionIfChanged` 改为返回 `error`。渠道保存的钩子只记日志；设置当前价接口把错误返回给前端。
- `UpdateChannel` 钩子：只有提交的成本字段相对**原 setting** 有变化，才调用 `appendCostVersionIfChanged`。比较沿用 `costVersionChanged` 的规则（把原 setting 当作一条版本来比）。
- 新增、修改、删除记录和设置当前价成功后，依次：`costCubeCacheClear()` → `model.SyncChannelCostSetting` → `model.InitChannelCache()`。同步失败只记日志，不让请求失败：版本已经写入，是成本的唯一依据，下次任何改动还会再同步。
- 设置当前价：校验 → 渠道必须存在 → `appendCostVersionIfChanged`（和此刻生效的价不同才追加，首条记录用 0）→ 同步。
- 审计（`recordManageAudit`）：

| action | 模板 |
|---|---|
| `cost.version_create` | Added a price record for channel #${channel_id} |
| `cost.version_update` | Edited a price record for channel #${channel_id} |
| `cost.version_delete` | Deleted a price record for channel #${channel_id} |
| `cost.price_set` | Set the current price for channel #${channel_id} |

参数：`channel_id`、`version_id`、`effective_from`、`before`、`after`。价格写成 `ratio 3.1`、`discount 0.31 × 6.8` 这样的短串。前端 `AUDIT_TEMPLATES` 加同样 4 条，7 种语言同步。

## 4. 新前端

### 4.1 价格记录面板

从 `edit-ratio-dialog.tsx` 拆到 `components/cost-version-history.tsx`（原文件已超过 600 行）。

- 每行：生效时间（或「初始」）、备注、价格描述、「编辑」「删除」按钮。
- 点「编辑」，该行原地换成表单，带出原值；初始记录的生效时间显示为「初始」，不可改；带日期记录用 `DateTimePicker`。
- 补录表单与编辑表单是同一个组件。生效时间多一个选择（`ToggleGroup`）：「初始」/「指定时间」。已有初始记录时「初始」禁用，并提示直接修改。
- 结算汇率输入框只在折扣模式显示（倍率模式用不到）。
- 没有初始记录、但有其它记录时，列表末尾显示「未设置初始价格：早于最早一条记录的日志按最早那条计价」和「设置」按钮，点开补录表单并选中「初始」。
- 删除用 `ConfirmDialog`（`destructive`）确认。

### 4.2 弹窗上半部分（当前价）

- 保存改调 `PUT /api/cost/channels/:id/price`，不再先读渠道再 `PUT /api/channel/`。
- 提示改为：只影响保存之后的日志；要更正以前的价格，请修改下面的记录。

### 4.3 图表（`cost-charts.tsx`）

参照 `dashboard/components/models/model-charts.tsx` 与 `consumption-distribution-chart.tsx`：
- 两张卡片改为上下排列、各占一行。
- 卡片头：`IconBadge`（趋势 `chart-4`，渠道 `chart-2`）+ 标题 + 灰色合计（趋势显示利润合计，渠道显示成本合计，按展示货币换算）。标题不再带 `(¥)`，坐标轴和合计已经带货币符号。
- 图表区：`h-[300px] p-1.5 sm:h-96 sm:p-2`。
- 收支趋势：`type: 'area'`、`stack: false`、面积 `fillOpacity: 0.08` + `curveType: 'monotone'`、线宽 2、不显示点、`legends.selectMode: 'single'`。颜色取数据看板色板 `getDashboardChartColors`：收入第 1 色（蓝）、成本第 3 色（橙）、利润第 4 色（绿），避免收入和成本都是蓝色。悬停提示保持收入、成本、利润的固定顺序。
- 渠道成本构成：色板换成 `getDashboardChartColors(域长度)`（≤10 不重复）；保留段间缝隙描边；悬停提示首行「合计」，渠道按金额降序，「其他」排最后。
- spec 构造抽成纯函数 `features/cost/chart-specs.ts`，便于测试。
